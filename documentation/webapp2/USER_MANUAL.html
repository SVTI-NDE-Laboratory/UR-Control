21 October 2026 • Complete the installation examples before operator handover.

1. Safety and conditions for use

Use the cobot only if you are trained and authorized, and the complete installation has an approved risk assessment and operating procedure. These checks do not replace the robot manual or the installation's safeguards.

Check before useRequired condition
Ambient temperatureUR15 specification: 0–50 °C. Performance is reduced from 35 °C upward. Apply any stricter limits for the tool, other equipment or approved installation.
Humidity and condensationUR15 limit: 90% relative humidity, non-condensing. Keep humidity below this limit and do not operate if condensation is present.
Personal protectionWear the safety shoes required for the workstation. Use eye protection and task-appropriate gloves where required by the risk assessment. Confirm the PPE requirements with the setup owner; PPE does not replace guarding. Secure long hair and avoid loose clothing or jewellery.
Installation and work areaCorrect tool/TCP, payload, fixture and routine; secure mountings; no damaged equipment; approved paths and clear work area. Know the actual robot position before moving.
Control and stoppingKnow the physical emergency-stop locations. Run only one robot-control application. Keep the PC awake, running and connected during a cycle.

Manufacturer references: UR15 technical specifications, application risk assessment and handling and PPE guidance. Use the manual matching the installed robot/controller. Safety footwear and other task-specific PPE are workplace requirements to be confirmed, not a blanket UR requirement for every task.

Simulation is not an offline test. The current script still moves the robot and can apply force during approach. Stop current action aborts without returning Home; it is not the installation's emergency-stop system.

2. First launch

  1. Extract the release package into a normal folder on a 64-bit Windows PC. Python is included; do not run the exe inside a zip.
  2. For a new installation, extract RTM Cobot Studio-default-data.zip. Put its RTM Cobot Studio folder in a writable location, for example %LOCALAPPDATA%. Do not overwrite existing working data. Starter robot programs, routine scripts and routines are copied only into an empty local data folder. After setup, the user manages these libraries; startup and upgrades do not restore deleted files or add starter files.
  3. Start RTM Cobot Studio.exe. If prompted, select the folder containing preferences.json; alternatively, select an empty folder to create defaults. An existing saved location is reused.
  4. In Settings, check the active data folder and routine. The supplied IP is 192.168.3.10 and the routine is routine.json. These are for the existing installation, not generic safe coordinates for another robot.
  5. Complete the safety checks and approved robot startup before commanding motion. The matching Apply Force URP must already be installed on the controller; the exe does not install it.

The browser opens automatically. If it does not, copy the local URL from the console. Opening the app alone does not move the robot. Use Close app to shut down; closing only the tab can leave it running.

3. App overview and controls

RTM Cobot Studio is a local control panel for moving the cobot and applying force at measurement positions. It opens in a browser on the control PC and sends commands to the physical robot. Choose a tab according to the work you want to do.

TabWhat it is for
Manual ModeChoose one saved position or movement sequence and run it when needed.
Flexible measurementChoose measurement positions yourself and apply force one position at a time.
Automatic measurementsDefine a line of measurement points and let the app carry out the sequence.
SettingsManage the installation's data folder and routine files, including creating new routine files.

A waypoint is a saved robot position. A routine is an ordered sequence of waypoint moves. The header provides Settings and Close app. The selected routine file is shown in Settings. The status panel stays visible beside the tabs so you can follow the current action.

Status panel

Use this panel to see what the app is doing and the robot's last reported position. TCP means the tool's working point. Plane coordinates give its X/Y position relative to the taught measurement area. Idle coordinates can be stale; “—” means unavailable.

IndicatorWhat it tells you
MovingGreen during reported movement or an active force program, including a stationary force hold.
Force modeGreen when the force program is active; it does not confirm a particular measured force.
AcquisitionGreen when the external acquisition client is connected.
ErrorRed when an error needs acknowledgement. Closing the message clears the indicator, not the cause.

Grey activity indicators mean inactive or unavailable. Their colours are operating feedback, not a safety clearance. Stop current action aborts the current action or session. During Flexible or automatic work, other tabs are locked until the session ends or is stopped.

Manual Mode

Use this tab when you want to choose each movement yourself: go to a known saved position or run a taught movement sequence. It does not automatically carry out a measurement line.

  1. Select a waypoint, review its motion type, speed and acceleration, then choose Go to waypoint.
  2. Assess any direct-path confirmation. Choose No if clearance is uncertain; confirmation does not plan a collision-free path.
  3. For Perform routine, first establish its displayed starting waypoint using the approved procedure. The routine uses its own stored motion values, not the manual fields.

Linear units are mm/s and mm/s²; joint units are rad/s and rad/s². Current manual caps are 150 for linear speed/acceleration and 0.5 for joint speed/acceleration. Those caps do not establish a safe value for every setup.

Flexible measurement

Use this tab to work at positions you choose within the taught measurement plane. You move to a position, apply force there, and repeat as needed before returning Home. This suits individual checks or a small set of manually chosen measurements.

  1. Establish Home using the approved procedure. Click Start program and wait for Ready after entry to the measurement plane.
  2. Enter X/Y in millimetres and click Move. X follows the taught low start-to-end line; Y follows the taught plane, not base Y.
  3. Review target force [N], settling time [s] and Hold [s], then click Apply force. Target force must be positive; settling time must be nonnegative. Hold is 0–8 seconds; zero releases immediately after settling/readiness. The cycle returns to its pre-force pose.
  4. Use End and return Home for normal exit. Stop current action aborts the session instead.

The normal range is X from zero to the taught length and Y from −400 to 0 mm. Out-of-range moves need confirmation; force application still requires the configured range. Flexible does not start the acquisition server. A Ready session still reserves the robot controls.

Automatic measurements

Use this tab for a repeatable series of measurements along a line. You define the positions and force settings first; the app then visits the points and performs each force cycle, using either a timer or signals from the acquisition program to continue.

ControlMeaning
Automatic fitOn: fits the taught span. Editing Step size preserves the step and calculates whole samples; editing Nb. points calculates spacing including both ends.
X start / X endPositions relative to the taught start. With fit off, Start + Step × (Count − 1) calculates the grey End field.
Y offset / ObstacleY shifts the line. Obstacle Position is the center. The read-only width comes from obstacle.width (default 200 mm); Start and End are calculated. It skips samples in that interval and uses the configured detour; it does not detect obstacles or certify clearance.
Points selectionAll measures all valid points. From point includes that original ID and every valid point after it. Custom opens a checklist with point IDs and X/Y positions; obstacle points cannot be selected. Selection does not renumber points.
Settling / Hold time [s]Settling delay and timer hold are side by side. Client feedback controls the hold when With RTM program is enabled.
With RTM programOn: acquisition-client feedback controls continuation. Off: RTM Cobot Studio's timer uses Hold duration. Both modes require the PC's release acknowledgement.
Maximum displacementApproach travel limit while attempting contact, not proof of clearance.
  1. Confirm Home; review the line preview, obstacle settings and force parameters.
  2. Results are saved under the Results directory in Settings. Measurements folder name identifies a new folder for this run. With Automatic date and time name checked, a template is shown until Start program creates the dated folder. Uncheck it to edit the initial name Measurements_01; an existing folder or file is rejected, so results are never overwritten.
  3. Click Start program, review confirmations and provide any required acquisition-client signals. Waiting for a client is not necessarily a fault.
  4. Monitor phase, point and progress. Verify normal completion/return; stopping a run does not guarantee Home.

Save as default replaces shared measurement defaults. Reset default reloads them and can discard edits. With a 1000 mm span and 300 mm step, samples stop at 900 mm; choosing four points with fit on instead includes both 0 and 1000 mm.

Load configuration opens a folder browser inside Results. Select a run folder containing measurement_configuration.json and load it; the page refreshes with its saved parameters, including the X range and point spacing. Loading leaves the saved run and shared defaults unchanged. Installed URP paths come from current defaults. Reset default clears imported settings.

The graph is titled Summary. Its Points list button lists every original ID, X/Y coordinates in the taught measurement frame, and its selection or obstacle status. The run section is titled Run measurements.

4. Settings and routines

Use Settings to choose which installation files the app uses. It is for managing folders and taught routes, rather than moving the robot. File selections generally take effect after restarting the app.

Local data: the base path is shown in full; useful file/directory paths are relative. Change folder selects existing data or copies current data to an empty folder, keeping the original. Restart after changing location.

Routine file: Change file lists routine JSON files and checks compatibility before saving. Restart to apply the choice. The selected routine filename is shown here in Settings.

  1. To create a file, choose a PolyScope .script export. The chooser starts in the library set by routine_scripts_directory in app_config.
  2. Review the prefilled Home-to-start and End-to-Home waypoint lists. Names must match the export. Measurement waypoints are fixed and grey.
  3. Review joint speed [rad/s], acceleration [rad/s²] and intermediate blend [mm]. Click Create file with a new filename.
  4. The app creates four entry/exit routines with reversed return routes and zero blend at each route's endpoints. Review the result, select it with Change file, then restart. Extraction success does not prove path clearance.

Do not edit configuration or taught files during an action. The setup owner must keep the robot IP, tool, routine and controller program path consistent.

5. Results, errors and updates

SituationAction
Results and backupAutomatic state, feedback, configuration, plan and logs are in the selected session folder. Raw RTM data may be stored separately. Back up local data with the app closed.
Wrong initial positionEstablish Home or the required routine start using the approved procedure. Check the actual position rather than relying on idle feedback.
Contact not reachedCheck the tool/workpiece, force and approach settings. Retry only after confirming the return result; Flexible can remain Ready after a verified return.
Safety, connection or return failureInspect the robot/pendant, retain the error and logs, and follow approved recovery. Do not repeatedly restart without finding the cause.
App updateClose the app, replace the exe and retain local data. Existing user files and controller programs are not replaced automatically.

The default-data archive contains initial files, not a backup of your taught changes or results. Save your completed installation manual under a separate filename so package regeneration does not replace your additions.

7. Installation example — updating Apply Force

Local source: profiles/default/robot_programs/apply_force.script. Seeded controller path: /programs/Projects/BAM TTS/Programs/Apply_Force/apply_force_v2.urp. Real source: apply_force_from_ur_settling.script; guarded travel simulation source: apply_force_simulation.script. Select separate URPs using force.program_path and force.simulation_program_path. Input double registers 43/44/45 set distance [m], settling [s], and target force [N]. Copying the local script alone does not update the URP. Simulation moves the configured distance along starting TCP Z+ at up to 5 mm/s, settles, waits for release, then returns. A 40 N resultant-force guard monitors travel, settling, measurement and return; it stops and aborts without automatic return. This software guard cannot guarantee a 50 N peak limit during stopping. Preserve the feedback/release handshake used by both timer and client-feedback modes.
